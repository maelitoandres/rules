# 规则目录说明

## ⚠️ 最重要的约定

> **目录名表示「流量从哪个国家出去」，不是「我人在哪个国家」。**

这是整个结构的地基。一旦被理解成"使用地点"，同一个域名就得在多个目录里重复——`schwab.com` 要走美国出口，无论你人在中国还是哥伦比亚，它都只属于 `US/`，只写一次。

反例（改造前的真实情况）：旧的 `CO_ISP_rule.list` 文件名是 CO，内容却是抖音域名（中国服务）。因为它混进了"我人在哥伦比亚"这个维度，结果是文件名和内容对不上，扩展到三地时必然重复维护。

---

## 目录结构

```
rule/
├── CO/      🇨🇴 哥伦比亚出口
│   ├── CO_ISP_social.list    → 🇨🇴 CO住宅-家里
│   └── CO_ISP_crypto.list    → 🇨🇴 CO住宅-公司
├── US/      🇺🇸 美国出口
│   └── US_rule.list          → 🇺🇸 美国出口
├── CN/      🇨🇳 中国出口
│   └── CN_rule.list          → 🇨🇳 中国出口
└── GLOBAL/  🚀 通用代理
    └── Global_rule.list      → 🚀 通用代理
```

**一个文件 = 一个策略组。** 命名规则：`{出口国}_{出口类型}_{用途}.list`

---

## 三条出口分别解决什么问题

| 文件 | 出口 | 解决的问题 | 装什么 |
|---|---|---|---|
| `CO/CO_ISP_social.list` | BD 住宅 IP（家里） | **身份**——住宅 IP 信誉，平台风控看的是 IP 稳不稳 | 抖音、微博、小红书、微信视频号、TikTok CO 运营 |
| `CO/CO_ISP_crypto.list` | BD 住宅 IP（公司） | **准入**——确保不是美国 IP | 加密货币平台 |
| `US/US_rule.list` | JMS 洛杉矶 | **常规**——美国出口 | Schwab、美股 |
| `CN/CN_rule.list` | 中国直连／回国节点 | 中国的服务 | 国内媒体、中国船公司、企查查 |
| `GLOBAL/Global_rule.list` | 通用代理 | 无地域归属 | Google、AI、Figma、国际船公司 |

两个 CO 文件用**不同的出口 IP**，让运营和交易天然隔离，互不影响对方的 IP 信誉。

---

## 各地点的策略映射

同一份规则，三地走向不同——差异全部在 `cfg/*.ini` 里，规则文件本身不需要任何改动：

| 策略组 | 🇨🇳 中国办公室 | 🇺🇸 美国办公室 | 🇨🇴 哥伦比亚办公室 |
|---|---|---|---|
| 🇨🇴 CO住宅-家里 | 哥伦比亚-家里 | 哥伦比亚-家里 | 哥伦比亚-家里 |
| 🇨🇴 CO住宅-公司 | 哥伦比亚-公司 | 哥伦比亚-公司 | 哥伦比亚-公司 |
| 🇺🇸 美国出口 | 洛杉矶 | **DIRECT** | 洛杉矶 |
| 🇨🇳 中国出口 | **DIRECT** | 回国节点 ⚠️ | 回国节点 ⚠️ |
| 🚀 通用代理 | 洛杉矶 | **DIRECT** | **DIRECT** |

前两行三地一致——运营绑定与所在地无关，平台看的是出口 IP 稳不稳，不是你人在哪。

⚠️ 目前没有中国落地节点，这两格暂时无法兑现。

---

## 怎么加一个新域名

只需回答一个问题：**它该从哪个国家出去？**

```
需要固定住宅 IP 做账号运营？  → CO/CO_ISP_social.list
是加密货币平台（须非美国）？  → CO/CO_ISP_crypto.list
是美国的服务？                → US/US_rule.list
是中国的服务？                → CN/CN_rule.list
以上都不是？                  → GLOBAL/Global_rule.list
```

放进去就行——**三地自动生效，`cfg/*.ini` 一个字都不用改。**

---

## 规则优先级

`cfg/*.ini` 里 `ruleset=` 的**出现顺序决定优先级，先匹配先生效**。

`CO/` 下的两个运营文件必须排在最前面。原因：抖音域名同时符合两条逻辑——按地域算它是"中国服务"（在中国该直连），按运营算它"必须走 CO 住宅 IP"。**运营绑定必须赢**，所以它得排在 `CN_rule` 前面。
