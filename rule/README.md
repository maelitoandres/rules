# 规则目录说明

## ⚠️ 最重要的约定

> **目录名表示「流量从哪个国家出去」，不是「我人在哪个国家」。**

这是整个结构的地基。一旦被理解成"使用地点"，同一个域名就得在多个目录里重复——`schwab.com` 要走美国出口，无论你人在中国还是哥伦比亚，它都只属于 `US/`，只写一次。

反例（改造前的真实情况）：旧的 `CO_ISP_rule.list` 文件名是 CO，内容却是抖音域名（中国服务）。因为它混进了"我人在哥伦比亚"这个维度，结果是文件名和内容对不上，扩展到三地时必然重复维护。

---

## 一个文件 = 一个策略组

```
rule/
├── CO/      🇨🇴 哥伦比亚出口（ISP 住宅 IP）
│   ├── CO_douyin.list        → 🎶 抖音       45 条
│   ├── CO_weibo.list         → 📕 微博       14 条
│   ├── CO_longbridge.list    → 📈 长桥        3 条
│   └── CO_crypto.list        → 🪙 加密货币    17 条
├── US/      🇺🇸 美国出口
│   └── US_rule.list          → 🇺🇸 美国出口
├── CN/      🇨🇳 中国出口
│   └── CN_rule.list          → 🇨🇳 中国出口
└── GLOBAL/  🚀 通用代理
    └── Global_rule.list      → 🚀 通用代理
```

按 **app / 场景**分文件，而不是把所有社媒堆成一个文件。这样每个 app 都能在面板上独立选择走哪个出口 IP，加新账号时只需加一个文件加一个组。

命名规则：`{出口国}_{app或用途}.list`

---

## 🔒 策略组的两条铁律

### 1. 一律使用 `select`，禁止 `url-test`

节点是固定的自建/ISP 出口，不是机场那种几十个节点需要测速择优。更关键的是：**`url-test` 会自动切换节点，而运营账号最怕的就是 IP 变动**——平台风控看的正是 IP 稳不稳。手动勾选、固定不动，才是运营场景要的行为。

### 2. 哥伦比亚的两个 IP 各自作为独立节点列在组里

```
custom_proxy_group=🎶 抖音`select`[]🇨🇴 哥伦比亚-家里`[]🇨🇴 哥伦比亚-公司`[]DIRECT
custom_proxy_group=🪙 加密货币`select`[]🇨🇴 哥伦比亚-公司`[]🇨🇴 哥伦比亚-家里`[]DIRECT
```

不再使用「只包一个节点的 `url-test` 包装组」——那是冗余的。每个业务组直接列出两个 IP 节点，在面板上手动固定其一。不同 app 可以绑不同 IP，信誉互不牵连。

候选顺序即默认值：社媒默认走「家里」，加密货币默认走「公司」。

## 各出口解决什么问题

| 出口 | 解决的问题 | 服务对象 |
|---|---|---|
| 🇨🇴 BD 住宅 IP | **身份**——住宅 IP 信誉，平台风控看 IP 稳不稳 | 抖音、微博、小红书、微信视频号、TikTok 运营 |
| 🇨🇴 BD 住宅 IP（另一个） | **准入**——确保不是美国 IP | 加密货币平台 |
| 🇺🇸 JMS 洛杉矶 | **常规**——美国出口 + socks5 桥接跳板 | Schwab、美股 |
| 🇨🇳 直连／回国节点 | 中国的服务 | 国内媒体、中国船公司、企查查 |

## 各地点的策略映射

同一份规则，三地走向不同——差异全部在 `cfg/*.ini` 里，规则文件本身不需要任何改动：

| 策略组 | 🇨🇳 中国办公室 | 🇺🇸 美国办公室 | 🇨🇴 哥伦比亚办公室 |
|---|---|---|---|
| 🎶 抖音 / 📕 微博 / 📈 长桥 | 哥伦比亚 IP | 哥伦比亚 IP | 哥伦比亚 IP |
| 🪙 加密货币 | 哥伦比亚 IP | 哥伦比亚 IP | 哥伦比亚 IP |
| 🇺🇸 美国出口 | 洛杉矶 | **DIRECT** | 洛杉矶 |
| 🇨🇳 中国出口 | **DIRECT** | 回国节点 ⚠️ | 回国节点 ⚠️ |
| 🚀 通用代理 | 洛杉矶 | **DIRECT** | **DIRECT** |

运营类三地一致——绑定与所在地无关，平台看的是出口 IP 稳不稳，不是你人在哪。

⚠️ 目前没有中国落地节点，这两格暂时无法兑现。

---

## 保护运营 IP 的硬性约束

住宅 IP 是最宝贵也最脆弱的资产，以下几条不能妥协：

1. **「🐟 漏网之鱼」绝不可包含哥伦比亚节点**——该组接的是所有未匹配流量，一旦被切过去，广告追踪、软件更新、各类 app 心跳都会从运营 IP 出去，污染极快且难以察觉。
2. **socks5 必须走加密桥接**——BD 节点是 socks5，协议无加密且认证明文（RFC 1929），从中国直连会让凭证在链路上裸奔。
3. **桥接失败必须断开，禁止降级直连**——宁可出口不通，也不能在故障时暴露凭证。
4. **只有明确列入本目录的域名才走运营 IP**——不给任何流量"顺便"走过去的机会。

## 怎么加一个新域名

只需回答一个问题：**它该从哪个国家出去？**

```
某个 app 需要固定住宅 IP 做运营？ → CO/ 下建对应 app 的 .list + 一个策略组
是加密货币平台（须非美国）？      → CO/CO_crypto.list
是美国的服务？                    → US/US_rule.list
是中国的服务？                    → CN/CN_rule.list
以上都不是？                      → GLOBAL/Global_rule.list
```

放进去就行——**三地自动生效，`cfg/*.ini` 一个字都不用改**（新建 app 组除外）。

---

## 规则优先级

`cfg/*.ini` 里 `ruleset=` 的**出现顺序决定优先级，先匹配先生效**。

`CO/` 下的文件必须排在最前面。原因：抖音域名同时符合两条逻辑——按地域算它是"中国服务"（在中国该直连），按运营算它"必须走 CO 住宅 IP"。**运营绑定必须赢**，所以它得排在 `CN_rule` 前面。
