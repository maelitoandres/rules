# 规则目录说明

## ⚠️ 最重要的约定

> **目录名表示「流量从哪个国家出去」，不是「我人在哪个国家」。**

这是整个结构的地基。一旦被理解成"使用地点"，同一个域名就得在多个目录里重复——`schwab.com` 要走美国出口，无论你人在中国还是哥伦比亚，它都只属于 `US/`，只写一次。

反例（改造前的真实情况）：旧的 `CO_ISP_rule.list` 文件名是 CO，内容却是抖音域名（中国服务）。因为它混进了"我人在哥伦比亚"这个维度，结果是文件名和内容对不上，扩展到三地时必然重复维护。

## 目录结构

```
rule/
├── CO/      🇨🇴 哥伦比亚出口（ISP 住宅 IP）
│   ├── CO_social_rule.list   → 🇨🇴 CO社媒运营   59 条
│   └── CO_crypto_rule.list   → 🇨🇴 CO冲浪快线   17 条
├── US/      🇺🇸 美国出口
│   └── US_rule.list          → 🇺🇸 美国出口      4 条
├── CN/      🇨🇳 中国出口
│   └── CN_rule.list          → 🇨🇳 中国出口     27 条
└── GLOBAL/  🚀 通用代理
    └── Global_rule.list      → 🚀 通用代理      17 条
```

**一个文件 = 一个策略组。** 命名规则：`{出口国}_{用途}_rule.list`

### 为什么社媒和加密货币要分成两个文件

因为它们必须用**不同的出口 IP**：一旦加密货币平台那边触发风控，共用 IP 会连累运营账号。这是唯一需要隔离的边界——抖音、微博、小红书之间**不需要**再细分，它们本来就是同一批运营账号在用，拆开只会增加维护负担。

### 自维护文件只放"上游没有的"

抖音、微博、小红书的通用域名，`blackmatrix7` 的上游规则集已经覆盖，且持续更新。ini 里让上游规则集**直接指向同一个策略组**即可，不必自己搬运：

```
ruleset=🇨🇴 CO社媒运营,https://.../blackmatrix7/DouYin.list        ← 上游，自动更新
ruleset=🇨🇴 CO社媒运营,https://.../blackmatrix7/Weibo.list         ← 上游
ruleset=🇨🇴 CO社媒运营,https://.../blackmatrix7/XiaoHongShu.list   ← 上游
ruleset=🇨🇴 CO社媒运营,https://.../rules/rule/CO/CO_social_rule.list  ← 只维护补充部分
```

多个规则集指向同一策略组是合法的，它们会合并生效。

## 🔒 策略组的两条铁律

### 1. 一律使用 `select`，禁止 `url-test`

节点是固定的自建/ISP 出口，不是机场那种几十个节点需要测速择优。更关键的是：**`url-test` 会自动切换节点，而运营账号最怕的就是 IP 变动**——平台风控看的正是 IP 稳不稳。手动勾选、固定不动，才是运营场景要的行为。

### 2. 哥伦比亚的两个 IP 各自作为独立节点列在组里

```
custom_proxy_group=🇨🇴 CO社媒运营`select`[]🇨🇴 哥伦比亚-家里`[]🇨🇴 哥伦比亚-公司`[]DIRECT
custom_proxy_group=🇨🇴 CO冲浪快线`select`[]🇨🇴 哥伦比亚-公司`[]🇨🇴 哥伦比亚-家里`[]DIRECT
```

不使用「只包一个节点的 `url-test` 包装组」——那是冗余的。业务组直接列出两个 IP 节点，在面板上手动固定其一。候选顺序即默认值：社媒默认走「家里」，加密货币默认走「公司」。

## 各出口解决什么问题

| 出口 | 解决的问题 | 服务对象 |
|---|---|---|
| 🇨🇴 BD 住宅 IP（家里） | **身份**——住宅 IP 信誉，平台风控看 IP 稳不稳 | 抖音、微博、小红书、微信视频号、TikTok 运营 |
| 🇨🇴 BD 住宅 IP（公司） | **准入**——确保不是美国 IP | 加密货币平台 |
| 🇺🇸 JMS 洛杉矶 | **常规**——美国出口 + socks5 桥接跳板 | Schwab、长桥 |
| 🇨🇳 直连／回国节点 | 中国的服务 | 国内媒体、中国船公司、企查查 |

## 各地点的策略映射

同一份规则，三地走向不同——差异全部在 `cfg/*.ini` 里，规则文件本身不需要任何改动：

| 策略组 | 🇨🇳 中国办公室 | 🇺🇸 美国办公室 | 🇨🇴 哥伦比亚办公室 |
|---|---|---|---|
| 🇨🇴 CO社媒运营 | 哥伦比亚-家里 | 哥伦比亚-家里 | 哥伦比亚-家里 |
| 🇨🇴 CO冲浪快线 | 哥伦比亚-公司 | 哥伦比亚-公司 | 哥伦比亚-公司 |
| 🇺🇸 美国出口 | 洛杉矶 | **DIRECT** | 洛杉矶 |
| 🇨🇳 中国出口 | **DIRECT** | 回国节点 ⚠️ | 回国节点 ⚠️ |
| 🚀 通用代理 | 洛杉矶 | **DIRECT** | **DIRECT** |

运营类三地一致——绑定与所在地无关，平台看的是出口 IP 稳不稳，不是你人在哪。

⚠️ 目前没有中国落地节点，这两格暂时无法兑现。

## 保护运营 IP 的硬性约束

住宅 IP 是最宝贵也最脆弱的资产，以下几条不能妥协：

1. **「🐟 漏网之鱼」绝不可包含哥伦比亚节点**——该组接的是所有未匹配流量，一旦被切过去，广告追踪、软件更新、各类 app 心跳都会从运营 IP 出去，污染极快且难以察觉。
2. **socks5 必须走加密桥接**——BD 节点是 socks5，协议无加密且认证明文（RFC 1929），从中国直连会让凭证在链路上裸奔。
3. **桥接失败必须断开，禁止降级直连**——宁可出口不通，也不能在故障时暴露凭证。
4. **社媒与加密货币永不共用 IP**——交易所触发的风控不应波及运营账号。
5. **只有明确列入本目录的域名才走运营 IP**——不给任何流量"顺便"走过去的机会。

## 怎么加一个新域名

只需回答一个问题：**它该从哪个国家出去？**

```
社媒运营账号要用的？      → CO/CO_social_rule.list
是加密货币平台（须非美国）？ → CO/CO_crypto_rule.list
是美国的服务？            → US/US_rule.list
是中国的服务？            → CN/CN_rule.list
以上都不是？              → GLOBAL/Global_rule.list
```

放进去就行——**三地自动生效，`cfg/*.ini` 一个字都不用改。**

加完记得检查是否与其它文件重复：

```bash
find rule -name '*.list' | xargs grep -hE '^DOMAIN' | sed 's/ *#.*//' | sort | uniq -d
```

## 规则优先级

`cfg/*.ini` 里 `ruleset=` 的**出现顺序决定优先级，先匹配先生效**。

`CO/` 下的文件必须排在最前面。原因：抖音域名同时符合两条逻辑——按地域算它是"中国服务"（在中国该直连），按运营算它"必须走 CO 住宅 IP"。**运营绑定必须赢**，所以它得排在 `CN_rule` 前面。
